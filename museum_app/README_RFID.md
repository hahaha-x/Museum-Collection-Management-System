# 模拟数据与真实 RFID 数据切换

## 开关位置

管理员登录后进入「RFID设备」→「数据源切换」，选择「模拟数据」或「真实设备」，点击「应用数据源」。
首次启用默认模拟；选择保存在 SQLite，重启后保持。切换到另一模式会暂停网页取数并隐藏前一模式结果，
然后点击「开始采集」。查看者和馆藏管理员可查看来源，但不能修改全系统开关。

原来的模拟正常读数、模拟空读、模拟故障按钮和模拟盘点逻辑均保留。
真实模式隐藏模拟按钮，并在服务端拒绝调用模拟注入接口，不会因 Reader 不在线而自动回退。

## 没有设备时

选择模拟数据并点击开始采集。不需要运行 C# 程序，也不需要配置密钥。
模拟故障后可点模拟正常读数恢复，或重新点击开始采集。

## 使用真实设备

1. 关闭 Gateway，确认电脑可以连接 Reader。
2. 为两个程序设置相同的随机密钥（至少 16 字符）。不要把密钥写入网页或提交到仓库。
3. 启动 C# 服务，再启动 Flask。两个 PowerShell 终端分别设置环境变量：

```powershell
# 终端一：替换为你生成的随机密钥
$env:RFID_API_TOKEN = '替换为同一个至少16字符的随机密钥'
cd D:\Project\museum\RFID_reader
.\bin\local\RfidCollector.exe
```

```powershell
# 终端二：与终端一完全相同；修改环境变量后要重启 Flask
$env:RFID_API_TOKEN = '替换为同一个至少16字符的随机密钥'
$env:RFID_API_URL = 'http://127.0.0.1:5080'
cd D:\Project\museum\museum_app
python app.py
```

4. 网页选择真实设备，点击开始采集。后台每 5 秒请求 C# `/observations/latest`。
5. EPC 会保留前导零、去空格并转大写。无标签时清空当前列表；服务失败、旧数据或错误来源不会显示为成功。
6. 真机暂时断连时继续按周期重试，恢复后显示新观测，始终不会调用模拟器补齐。

服务地址及密钥只用于 Flask 后端。浏览器仍只访问 Flask，不直接访问 C#。
默认按单 Flask 服务进程运行；debug 重载不在父进程重复启动采集线程。
如未来部署多个 WSGI worker，应先将轮询迁移到独立调度进程。

## 重要备注

- 这个开关切换的是 RFID 数据来源，不是库存数据库。模拟模式中办理的出入库仍会更新当前库。
  无设备调试建议使用测试藏品，或通过 MUSEUM_DB_PATH 指定另一份测试数据库。
- 原 museum.db 不需要删除或重新初始化。程序第一次连接数据库时增量创建
  rfid_source_state、rfid_batches 两张表；不删除藏品、库存、流水、旧标签记录或旧告警。
- 批次按来源和切换代次隔离，重复读取同一真实 observation_id 不重复写入。
  切换期间返回的旧 HTTP 响应会被丢弃；切回旧模式也不会复用上次模式的旧批次。
- 「暂停采集」只暂停 Flask 取数，不关闭 C# 服务、不控制 Reader 射频。要停止硬件采集，在 C# 终端按 Ctrl+C。
- 当前批次列表最多展示 10 个 EPC，空读、故障或过期会清空列表；历史批次保留在数据库中。
- 模拟告警保留，新增模拟告警的原因带 [模拟数据] 标记；历史告警不会因切换被删除。
  真机模式不会套用“一轮缺读立即报警”的模拟规则；正式离架告警仍需连续有效窗口和授权校验。
- 自动盘点跟随同一开关。真实模式使用最近有效观测做比对，而不是模拟列表；
  尚未验证全库/区域天线覆盖，因此真实比对一律标记为「不完整」，不能据此认定藏品丢失。
  历史盘点详情显示其原始来源，不随当前模式改变。
- 本次没有新增入库 RFID 强制实物核验。现有出入库权限、状态流转和事务逻辑保持原样；
  页面显示真实标签不等于入库已经强制验证该标签，后续应接入 POST /scans 流程。
- 新批次表暂不自动清理，持续运行应后续制定日志归档策略。

## 测试

```powershell
cd D:\Project\museum\museum_app
python -m unittest test_rfid_modes -v
```

测试使用临时 SQLite 和本机假 HTTP 服务，不连接真实 Reader，不修改 museum.db。
包含模式切换、权限、CSRF、模拟保留、真机故障不回退、恢复、空读、过期、来源校验、切换竞态和模板渲染。
真实标签识读与真实 Reader 断线恢复仍需实验课验证。
